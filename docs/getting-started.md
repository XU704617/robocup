# 新人从这里开始

[返回目录](../README.md)

## 尚未加入队伍

1. 读[赛事概览](introduction.md)，确认 HSL 与其他足球组的区别。
2. 从[HSL 官方网站](https://hsl.robocup.org/)进入规则、邮件列表和新队伍说明；阅读规则时先看发布版本，不以仓库 `main` 分支的草稿代替正式规则。
3. 在[2026 队伍名单](https://hsl.robocup.org/qualified-teams/)中挑一支队伍，读其 TDP（队伍技术说明）和软件资料，列出不理解的术语。
4. 按[学习路线](learning.md)完成 Git 和机器人基础，再选一个公开项目做[首次运行](first-run.md)。

## 已加入队伍

先问清目标赛事与组别、机器人型号、负责模块、主仓库与分支、开发环境和测试方式。把这些写成个人任务记录，然后完成最小复现：能获取代码、按项目说明启动一个示例、保存命令与实际输出。后续再读该模块的接口和测试。

## 一周内可以交付的小成果

- 画出“传感器 → 感知/定位 → 决策 → 运动控制”的队伍软件链路，标出自己负责的模块。
- 复现一个公开或队内示例，记录环境、命令、预期与实际结果。
- 找到当届规则中与自己模块有关的一条约束，附规则版本和章节。

比赛报名、资格材料和期限见[参赛流程](participation.md)与[年度赛事资料](../events/README.md)。

## 新人两周练习安排

这是一份可调整的学习安排，并非联赛要求。队伍若有现成的入门任务，应优先使用队伍实际代码和设备。

| 时间 | 任务 | 留下什么证据 |
| --- | --- | --- |
| 第 1—2 天 | 读[赛事概览](introduction.md)、[术语表](glossary.md)，找到正式规则的版本 | 一页笔记：赛事、组别、规则标签与来源 |
| 第 3—4 天 | 读[系统结构](system-overview.md)，选一支[公开队伍](../resources/teams.md)阅读 TDP | 一张模块图；三条 TDP 中“已实现”与“计划中”的区分 |
| 第 5—7 天 | 完成[首次运行](first-run.md)，学会记录错误 | 环境、命令、输出、截图或日志；失败也记录原因 |
| 第 2 周 | 选感知、运动、行为或通信中的一个模块，按[学习路线](learning.md)做最小练习 | 一个可重复的输入、输出和验收条件 |

如果连队伍的平台都未确定，先做官方规则、GameController 和公开 TDP 的练习；不要为了“跑起来”随意购买硬件或把陌生软件写入机器人。

## 向老队员问哪些具体问题

把“应该学什么”拆成可回答的事项：机器人型号和软件版本是什么、代码托管在哪里、谁维护构建环境、我负责的模块输入输出是什么、怎样在仿真或备用机验证、哪些操作必须有人陪同。得到答案后再决定是否要学习 ROS 2、某个仿真器或特定深度学习框架。
